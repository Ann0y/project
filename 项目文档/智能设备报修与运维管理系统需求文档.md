# 智能设备报修与运维管理系统 需求规格说明书

> 课题名称：智能设备报修与运维管理系统的设计与开发
> 文档版本：v1.0　　编制日期：2026-10-12
> 适用对象：毕业设计（信息学院 · 软件技术（前端开发）教研室）

---

## 1. 项目概述

### 1.1 建设目标

面向高校/园区场景，构建一套 B/S 架构的设备报修与运维管理系统，替代"电话报修—纸质登记—人工派单"的传统模式，实现：

- **统一入口**：扫码/检索即可报修，故障描述带图，信息一次到位；
- **全程闭环**：工单从提交到验收归档全状态可视、可追溯；
- **知识沉淀**：每次维修沉淀为结构化记录，可检索、可推荐、可复用；
- **主动预防**：基于健康度评分与维保周期生成预警，把"事后抢修"前移；
- **数据决策**：ECharts 看板呈现报修趋势、故障分布、响应时效等关键指标。

### 1.2 适用范围边界

| 纳入范围 | 不纳入范围 |
| --- | --- |
| 设备台账、报修工单、维保计划与记录、配件库存、统计看板 | 物联网传感器实时采集 |
| Web 端（PC + 移动端自适应） | 独立原生 App / 微信小程序（可作为扩展） |
| 规则型推荐与健康度评分 | 深度学习故障预测模型 |

## 2. 用户角色与入口

| 角色 | 来源 | 核心职责 | 入口与可见功能 |
| --- | --- | --- | --- |
| **报修人**（师生/教职工） | 前台自助注册 | 提交报修、跟踪进度、验收评价 | 前台报修端：设备浏览、在线报修、我的工单、服务评价、我的报修统计 |
| **维修人员**（运维工程师） | 管理员后台建号 | 接单/转单、完工登记、自检巡检录入 | 维修工作台：工单池与接单、完工登记、巡检维保、工作台概览图表 |
| **系统管理员** | 内置/后台创建 | 设备台账维护、派工与改派、用户管理、字典、看板 | 后台管理端：全部后台功能 + 运维数据看板 |

**登录与鉴权**：登录态由 **Session** 承载（Cookie 中的 `JSESSIONID`），有效期 2 小时，采用**滑动过期**实现无感刷新；后端通过 `HandlerInterceptor` 拦截受保护接口，**仅校验"是否已登录"**，不做接口级角色鉴权。前端按用户角色渲染不同入口与菜单（前台报修端 / 维修工作台 / 后台管理端），三者复用同一套接口。

> 范围说明：本期**不实现细粒度权限模型**（不设权限点、不做接口级角色校验），以登录态保护接口、以角色区分前端入口；接口级角色鉴权列入后续扩展。

> 数据可视化入口说明：按任务书"前端界面至少包括…数据可视化"的要求，**报修端与维修端也具备可视化入口**——报修人查看"我的报修统计"，维修人员查看"我的工作量/好评率图表"，管理员查看全局看板（E3）。

## 3. 业务流程

### 3.1 报修主流程

```
报修人登录 → 扫码/检索选中设备 → 填写故障现象 + 上传图片 + 选择紧急程度
   → 系统生成工单号并按(紧急程度, 故障等级)计算初始优先级
   → 状态：待受理
管理员派工（推荐维修人员） → 状态：已派工
维修人员接单              → 状态：维修中
完工登记（原因/措施/配件/工时） → 状态：待验收
报修人验收 + 满意度评价    → 状态：已完成 → 归档关闭（已关闭）
   └ 验收不合格 → 状态：维修中（返修，记录驳回原因，重新完工后再次验收）
```

工单状态：`待受理 → 已派工 → 维修中 → 待验收 → 已完成 → 已关闭`；异常状态：`已撤销`（报修人在"待受理"前撤销）。

异常分支：维修人员可**转单**（写原因）、**退单**（写说明回退至待受理）；管理员可**改派**（重新指派维修人员）；超时未处理的工单在看板中高亮并向相关人推送站内催办提醒。

### 3.2 维保预警流程

```
定时任务（每日 09:00）扫描 eq_info
   → 计算 健康分 H = w1·故障频次 + w2·故障等级 + w3·服役年限 + w4·距上次维保间隔
   → H < 60 判定亚健康，写入 health_score 表
   → 同时距离下次维保日 ≤ 7 天，生成"维保待办"
   → 管理员后台/看板展示亚健康清单与待办，可一键生成维保工单
```

### 3.3 相似工单推荐流程

```
输入故障描述文本 → 分词/关键词提取 → 关键词倒排召回候选集
   → 综合打分 = 0.4·关键词匹配度 + 0.3·设备类别一致 + 0.3·故障标签余弦相似度
   → Top-N 返回（相似工单 + 其历史解决方案）
```

## 5. 增强（智能）功能

### E1 关键词检索 + 相似工单推荐 【增强功能 · 推荐项】

- 建立工单标题、故障描述、解决方案的关键词索引；
- 倒排召回 + 多因子加权排序（见 3.3）；
- 输出：相似历史工单列表（含解决方案摘要）；
- 冷启动处理：无候选时回退为按设备类别的热门工单。

### E2 设备健康度评价与维保预警 【增强功能 · 推荐项】

- 规则评分模型（满分 100）指标：近 12 个月报修次数、最高故障等级、服役年限、距上次维保天数；
- 输出健康等级：健康（≥80）/ 关注（60-79）/ 亚健康（<60）；
- 预警：健康分低于阈值或维保到期 ≤7 天 → 生成维保待办，可一键转维保工单。

### E3 运维数据可视化看板 【增强功能 · 对应任务书"数据可视化"界面要求】

ECharts 图表清单：

| 图表 | 类型 | 指标 |
| --- | --- | --- |
| 报修量趋势 | 折线图 | 近 12 个月/近 30 天报修量 |
| 故障类型分布 | 饼图/环形图 | 各故障分类占比 |
| 楼栋/区域分布 | 柱状图 + 热力色块 | 各楼栋故障数 |
| 响应与修复时效 | 双轴柱线图 | 平均响应时长 MTTR、平均修复时长 |
| 工单完成情况 | 堆叠柱状图 | 各状态工单数量 + 完成率 |
| 维修人员工作量 | 横向柱状图 | 个人接单量、平均处理时长、好评率 |
| 配件消耗 TOP10 | 词云/柱状图 | 配件出库量排行 |
| 我的报修统计（前台） | 折线图 / 环形图 | 报修人本人的报修量与状态分布（任务书要求前端亦有数据可视化） |

支持统一筛选：时间范围、楼栋、设备类别、故障类型。

## 6. 数据对象设计（核心业务表 + 配套支撑表）

| 表名 | 说明 | 主要字段 |
| --- | --- | --- |
| `sys_user` | 用户 | id, username, password(密文), real_name, phone, role_id, status, create_time |
| `sys_role` | 角色 | id, role_code, role_name, remark |
| `eq_category` | 设备分类 | id, name, parent_id, sort |
| `eq_info` | 设备台账 | id, code(唯一), name, category_id, building, location, spec, purchase_date, maintain_cycle, responsible_user_id, status, qr_code, del_flag |
| `repair_order` | 报修工单 | id, order_no(唯一), device_id, reporter_id, title, description, images, fault_type, urgency, priority, status, repair_user_id, create_time, accept_time, finish_time, close_time |
| `order_flow` | 工单流转记录 | id, order_id, from_status, to_status, operator_id, opinion, operate_time |
| `repair_record` | 维修完工记录 | id, order_id, cause, solution, hours, images, create_time |
| `part_info` | 配件库存 | id, name, spec, stock, threshold, unit |
| `part_used` | 配件领用流水 | id, part_id, order_id, quantity, operator_id, create_time |
| `maintain_record` | 巡检/维保记录 | id, device_id, type(巡检/保养), content, result, executor_id, execute_time, next_time |
| `health_score` | 设备健康评分 | id, device_id, score, level, factor_detail(JSON), calc_date |
| `order_comment` | 工单评价 | id, order_id, response_score, attitude_score, quality_score, content, create_time |

**配套支撑表**（业务功能依赖，随主体一并实现）：`sys_dict` / `sys_dict_item`（数据字典：设备分类、故障类型、紧急程度、维保周期、楼栋等可配置项）、`sys_log`（操作日志）、`notification`（站内消息，含未读标记）、`attachment`（统一附件管理）。

**设计要求**：全部含主键 id；`repair_order.device_id → eq_info.id`、`repair_order.repair_user_id → sys_user.id` 等建立外键/逻辑关联；`eq_info.code`、`repair_order.order_no`、`repair_order.status + create_time` 建立索引；金额与工时用 DECIMAL，时间统一 DATETIME，删除采用逻辑删除字段 `del_flag`。

## 7. 接口设计约定

- 基础路径：`/api/v1/**`，全部返回 JSON，统一封装 `{code, message, data, timestamp}`；
- 认证：基于 Cookie 的 Session（`JSESSIONID`），未登录/会话过期返回 `401`；开发阶段通过 Vite 代理使前后端同源，避免跨域 Cookie 问题；

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/auth/register` `/auth/login` | 注册 / 登录（建立 Session） |
| GET | `/api/v1/users/me` | 当前登录用户信息 |
| GET | `/api/v1/users` POST PUT DELETE | 用户管理（管理员） |
| GET | `/api/v1/devices` `?building=&category=&keyword=&status=&page=` | 设备分页检索 |
| GET/POST/PUT/DELETE | `/api/v1/devices/{id}` | 设备详情 / 新增 / 修改 / 删除 |
| POST | `/api/v1/repair-orders` | 提交报修（含图片上传） |
| GET | `/api/v1/repair-orders/my` `/assigned` | 我的报修 / 派给我的工单 |
| PATCH | `/api/v1/repair-orders/{id}/status` | 状态流转（受理/派工/接单/完工/验收/关闭） |
| POST | `/api/v1/repair-orders/{id}/comments` | 提交评价 |
| GET | `/api/v1/repair-orders/{id}/similar` | 相似工单推荐 |
| GET | `/api/v1/devices/{id}/health` | 设备健康度与维保建议 |
| GET | `/api/v1/statistics/overview` `?start=&end=&building=` | 看板汇总数据 |
| GET/POST | `/api/v1/parts` `/parts/{id}/stock` | 配件库存与出入库 |
| PATCH | `/api/v1/repair-orders/{id}/assign` | 派工 / 改派（管理员） |
| POST | `/api/v1/repair-orders/{id}/urge` | 催办 |
| POST | `/api/v1/files/upload` | 统一文件/图片上传（返回访问 URL） |
| GET/PUT | `/api/v1/notifications` | 站内消息列表 / 标记已读 |
| GET/POST/PUT/DELETE | `/api/v1/dicts` `/dicts/{type}` | 数据字典维护 |
| GET | `/api/v1/logs` | 操作日志查询（管理员） |
| GET | `/api/v1/export/{type}` | 数据导出（Excel：工单 / 台账 / 配件流水 / 统计） |

## 8. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 架构 | B/S，前后端分离；前端 Vue3 + Vite + Element Plus + ECharts；后端 Spring Boot + MyBatis-Plus；数据库 MySQL 8.x |
| 性能 | 校园网环境下主要页面首屏 ≤ 3s；列表接口响应 ≤ 1s（分页 + 索引优化） |
| 兼容性 | Chrome / Edge / Firefox 最新两个大版本；移动端 ≤768px 响应式适配 |
| 安全 | 前后端双向输入校验；Session 登录态 + 登录拦截器；MyBatis 参数化查询防 SQL 注入；文件上传类型白名单 + 大小限制 + 重命名存储；XSS 转义 |
| 可靠性 | 统一异常处理与友好提示；关键写操作事务保证；操作日志可追溯（F15） |
| 易用性 | 表单即时校验提示；空状态与加载态；关键操作二次确认；工单状态色标化 |
| 可维护 | 前端组件化与 API 层集中封装；后端 Controller/Service/Mapper 分层；统一响应体与全局异常处理器 |
