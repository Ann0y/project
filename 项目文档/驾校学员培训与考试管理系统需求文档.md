# 驾校学员培训与考试管理系统 需求规格说明书

> 课题名称：驾校学员培训与考试管理系统的设计与实现
> 文档版本：v1.1（精简版 + 教练角色）　　编制日期：2026-10-15
> 适用对象：毕业设计（信息学院 · 软件技术（前端开发）教研室）

---

## 1. 项目概述

### 1.1 建设目标

面向中小型机动车驾驶培训机构，构建一套 B/S 架构的学员培训与考试管理系统，替代"纸质档案 + 手工表格 + 电话约车"的传统管理方式，实现：

- **统一入口**：报名、分车、约车、学时、考试等业务集中在一个平台办理，信息一次录入、多处复用；
- **全程闭环**：报名 → 培训 → 约车 → 学时审核 → 考试 → 成绩 → 结业，全流程状态可视、可追溯；
- **学时规范**：按《机动车驾驶培训教学大纲》的准驾车型学时要求登记与审核学时；
- **预约有序**：学员在线预约培训时段，服务端做时段冲突检测与状态校验，避免重复、冲突预约；
- **数据决策**：ECharts 看板呈现报名、学时、考试通过率等关键指标，辅助经营决策；
- **自助服务**：学员可自助查询报名状态、已学学时、各科目进度与考试成绩。

### 1.2 适用范围边界

| 纳入范围 | 不纳入范围 |
| --- | --- |
| 学员档案、教练与车辆、培训课程与学时、约车预约、考试与成绩、统计报表 | 车载计时终端 / 人脸识别的硬件级学时采集（本期以人工登记 + 审核为主） |
| Web 端（PC + 移动端自适应） | 独立原生 App / 微信小程序 |
| 规则型的时段冲突检测与通过率统计 | 基于历史数据的深度学习预测模型 |
| 学员 / 教练 / 管理员三端功能 | 与第三方监管平台的实时接口对接 |

> 本期为**精简版本**，聚焦核心业务闭环；被裁剪的非必要功能见 **附录 A**，后续按需扩展。

## 2. 用户角色与入口

| 角色 | 来源 | 核心职责 | 入口与可见功能 |
| --- | --- | --- | --- |
| **学员** | 前台自助注册 / 后台建号 | 报名、预约培训、查看进度与成绩 | 学员端：我的培训进度、培训与约车、我的考试与成绩、个人中心 |
| **教练** | 管理员后台建号（与教练档案绑定） | 维护本人排课时段、确认预约、登记学时、查看带教学员 | 教练端：教练工作台、我的排课、预约处理、学时登记、我的学员 |
| **系统管理员** | 内置 / 后台创建 | 学员管理、教练与车辆管理、培训与学时审核、考试安排、统计报表、用户管理 | 后台管理端：工作台 + 全部后台功能 + 统计报表 |

**登录与鉴权**：登录态由 **Session** 承载（Cookie 中的 `JSESSIONID`），默认有效期 30 分钟，采用**滑动过期**实现无感刷新；后端通过 `LoginInterceptor` 拦截 `/api/**`（放行 `login/register/logout` 与 CORS 预检），**仅校验"是否已登录"**，不做接口级角色鉴权。前端按登录角色渲染不同入口与菜单，并通过路由守卫限制各角色专属页面。

> 权限说明：本期以**角色字段 + 前端路由守卫**实现权限区分，不做接口级角色校验与细粒度权限点；RBAC 权限模型列入后续扩展。

> 数据可视化入口说明：按任务书"前端界面至少包括…数据可视化"的要求，**学员端与管理员端均具备可视化**——学员查看"我的培训进度"图表，管理员查看工作台指标与统计报表（E2）。

## 3. 业务流程

### 3.1 报名与入学主流程

```
学员注册（或管理员建号） → 提交报名信息（身份证 / 准驾车型 / 联系方式）
   → 管理员审核报名资料 → 登记缴费 → 状态：在训
   → 分配教练与教练车辆（生成带教关系）
   → 学员端"我的培训进度"显示准驾车型、教练、车辆、学时进度
```

学员状态：`待审核 → 在训 → 结业`；异常状态：`退学`。

### 3.2 培训与约车主流程

```
教练维护本人可预约时段 → 学员选择教练 + 时段 → 提交预约
   → 服务端冲突检测：同一学员 / 教练 / 车辆在该时段是否已占用
   → 校验学员状态（在训）→ 预约状态：待确认
教练 / 管理员确认预约 → 状态：已确认
学员按约到场完成培训 → 教练登记本次学时 → 预约状态：已完成
   → 生成学时记录 → 状态：待审核
管理员审核学时 → 通过：计入已学学时并更新科目进度；驳回：状态：已驳回（需说明原因）
```

预约状态：`待确认 → 已确认 → 已完成`；异常状态：`已取消`（确认前取消）、`爽约`（逾期未到）。
学时记录状态：`待审核 → 已通过 / 已驳回`。

### 3.3 考试与成绩流程

```
管理员发布考试计划（科目 / 日期 / 考场 / 容量）
   → 学员报名（校验学时是否满足该科目报考条件）
   → 管理员确认名单
   → 录入考试成绩与合格状态 → 合格：科目通过；不合格：生成补考记录
   → 全部科目合格且学时达标 → 学员状态置为结业
```

成绩状态：`待考 → 合格 / 不合格 → 补考中`。

## 5. 增强功能

### E1 预约时段冲突检测 【增强功能 · 核心保障】

- 预约提交时，基于"教练 × 车辆 × 时段"的占用表做冲突检测；
- 返回可用 / 冲突结论与冲突原因（学员冲突、教练冲突、车辆冲突）；
- 目的：避免重复预约与时段冲突，保证排课数据一致。

### E2 运营数据可视化看板 【增强功能 · 对应任务书"数据可视化"界面要求】

ECharts 图表清单：

| 图表 | 类型 | 指标 |
| --- | --- | --- |
| 报名量趋势 | 折线图 | 近 12 个月 / 近 30 天报名人数 |
| 准驾车型分布 | 饼图 / 环形图 | 各准驾车型报名占比 |
| 考试通过率 | 柱状图 / 仪表盘 | 各科目通过率与补考率 |
| 培训学时统计 | 双轴柱线图 | 各科目 / 各教练月培训学时 |
| 教练工作量 | 横向柱状图 | 各教练带教学员数、排课时长 |
| 我的培训进度（学员端） | 环形图 / 进度条 | 学员本人学时完成率、各科目进度（任务书要求前端亦有数据可视化） |

支持统一筛选：时间范围、准驾车型、科目、教练。

| 表名 | 说明 | 主要字段 |
| --- | --- | --- |
| `sys_user` | 登录用户 | id, username(唯一), password(BCrypt 密文), name, role(admin/coach/student), status, create_time |
| `student` | 学员档案 | id, user_id, id_card(唯一), name, phone, license_type, enroll_date, status(待审核/在训/结业/退学), coach_id, vehicle_id, del_flag |
| `coach` | 教练档案 | id, user_id, code(唯一), name, phone, license_types(准教车型), status |
| `vehicle` | 教练车辆 | id, plate_no(唯一), model, coach_id, status(可用/维修/停用), del_flag |
| `train_course` | 培训课程 / 科目学时配置 | id, license_type, subject_code, subject_name, required_hours |
| `coach_schedule` | 教练排课时段 | id, coach_id, vehicle_id, schedule_date, start_time, end_time, capacity, status |
| `booking` | 培训预约（约车） | id, student_id, coach_id, vehicle_id, schedule_id, book_date, status(待确认/已确认/已完成/已取消/爽约), create_time |
| `hours_record` | 学时记录 | id, student_id, subject_code, coach_id, booking_id, hours, train_date, audit_status(待审核/已通过/已驳回), auditor_id, audit_opinion, audit_time |
| `exam_plan` | 考试计划 | id, subject_code, exam_date, exam_time, venue, capacity, enrolled_count, status |
| `exam_record` | 考试报名与成绩 | id, plan_id, student_id, register_time, score, passed, attempt_no(第几次), status(待考/合格/不合格/补考中), exam_date |
| `payment` | 缴费记录 | id, student_id, item(培训费/补考费/其它), amount, pay_time, pay_method, status, operator_id |

**设计要求**：全部含主键 id；`student.user_id → sys_user.id`、`coach.user_id → sys_user.id`、`student.coach_id → coach.id`、`booking.student_id → student.id`、`booking.schedule_id → coach_schedule.id`、`hours_record.student_id → student.id`、`exam_record.student_id → student.id`、`payment.student_id → student.id` 建立外键 / 逻辑关联；`sys_user.username`、`student.id_card`、`coach.code`、`vehicle.plate_no` 建立唯一索引，`booking(schedule_id, status)`、`hours_record(student_id, subject_code)`、`exam_record(plan_id, student_id)` 建立联合索引；金额用 DECIMAL，时间统一 DATETIME，删除采用逻辑删除字段 `del_flag`。

## 7. 接口设计约定

- 基础路径：`/api/**`，全部返回 JSON，统一封装 `{code, message, data}`（`code=200` 表示成功）；
- 认证：基于 Cookie 的 Session（`JSESSIONID`），未登录 / 会话过期返回 `code=401`；跨域通过 `WebConfig` 的 CORS 配置放行本地来源并 `allowCredentials=true`，前端 Axios 需 `withCredentials=true`；
- 参数校验：`@Valid` + 全局异常处理器（`GlobalExceptionHandler`）统一转换为 `{code, message}`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/register` `/api/auth/login` `/api/auth/logout` | 注册 / 登录（建立 Session）/ 登出（销毁 Session） |
| GET | `/api/auth/me` | 当前登录用户信息 |
| GET/POST/PUT/DELETE | `/api/users` `/api/users/{id}` | 用户管理 + 角色分配（管理员） |
| GET | `/api/students` `?name=&idCard=&status=&licenseType=&coachId=&page=` | 学员分页检索（多条件组合） |
| GET/POST/PUT/DELETE | `/api/students/{id}` | 学员档案详情 / 新增 / 修改 / 删除 |
| POST | `/api/students/{id}/audit` | 报名审核（通过 / 驳回） |
| GET/POST/PUT/DELETE | `/api/coaches` `/api/vehicles` | 教练 / 车辆增删改查 |
| GET/POST/PUT/DELETE | `/api/schedules` | 排课时段查询与维护（教练维护本人时段） |
| GET/POST | `/api/bookings` `?status=&page=` | 预约列表 / 提交预约（含冲突检测） |
| PATCH | `/api/bookings/{id}/status` | 预约状态流转（确认 / 取消 / 完成 / 爽约） |
| GET/POST | `/api/hours` | 学时记录查询 / 登记（教练登记） |
| PATCH | `/api/hours/{id}/audit` | 学时审核（通过 / 驳回） |
| GET/POST/PUT/DELETE | `/api/exam-plans` `/api/exam-plans/{id}` | 考试计划维护 |
| POST | `/api/exam-plans/{id}/register` | 考试报名 |
| POST | `/api/exam-scores` | 成绩录入 |
| GET | `/api/exam-scores/my` | 我的考试成绩（学员） |
| GET/POST | `/api/payments` | 缴费记录查询 / 登记 |
| GET | `/api/statistics/overview` `?start=&end=&licenseType=&subject=&coachId=` | 看板 / 报表汇总数据 |

## 11. 对照任务书验收自检清单

> 依据：《信息学院毕业设计任务书（指导教师：刘艳梅）》"主要技术指标 → 3. 界面"等原文逐条核对。
